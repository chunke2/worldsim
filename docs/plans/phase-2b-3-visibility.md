# 2B-3：已提交事件的角色局部观察

## 修改前判断

1. 已确认问题：新认知存储尚没有从事实日志分发观察的入口；旧 EventCard/编年史/作者规划不能直接视为角色知识。
2. 优先级：P1 角色认知与信息传播；重放去重、来源分支核对和失败不污染属于 P0。
3. 验证收益：仅从磁盘 event_log.jsonl 中、注册世界版本以内的 Occurrence 生成观察；精确匹配 Audience，不按当前同房间自动扩散。
4. 最小证明：真实 StateEngine 提交的固定五人事件、私语/观察/移动/转述/无受众材料、重放、写失败、来源变化及分支测试，全部临时数据，无 LLM。

## 决策

- 事实源是事件日志，不接受临时提案、模型返回值或调用者提供的事件数组。注册表 WorldRevision 是可见提交上限；更晚的日志尾部不分发。
- 只处理 observation/utterance Occurrence。Reason、Changes、SourceEvents、编年史、世界书和旧迁移归档均不是观察正文来源。
- observation 采用现有提交语义：Actor 是观察者，Audience 必须只包含该观察者，多个视角需要分别提交，避免第一人称观察被复制给别人。
- utterance 精确分发给记录中的受众，保留说话人、地点和原话；这是“听到了陈述”，不是“陈述已经成为真相”。不因读者知道、人物同处一室或说话人身份自动扩大受众。
- 历史可见性以提交时 Audience 为准，不以角色现在的位置或存活状态重算。后续转述需要新的明确发言事件。
- 每条投影有稳定 ID、提交来源、事件 ID 和内容摘要。重放只补缺失条目，不重复写入；已有来源与当前投影不同则停止，不覆盖或遗忘旧认知。
- 单角色预览与分发可调用；全部角色分发先验证全部认知，之后按角色原子写入。若中途磁盘错误，可重试，已完成角色不重复。不是跨多文件数据库事务。
- 提供 Simulator 的显式桥接方法；不把新存储塞入旧主角/NPC 提示词，也不改变旧模拟行动管线。2B-4 的独立请求将使用此入口，2C 才替换行动循环。

## 边界

事件日志是受信任的本地提交记录，不是密码学签名。现有引擎在提交时检查受众位置，投影不从缺失的历史快照重新证明位置合法性。尚不能证明世界 AI 产生的每条观察在语义上正确；本步提供受众和来源边界，角色自主感知/行动仍未实现。

同版本分支检测覆盖有已投影记录的日志条目，不能证明日志中所有未投影世界状态的分支一致性。完整世界与认知分支恢复仍需要后续设计。

## 已实现接口

```text
NewVisibilityProjector(worldDir)
Projector.Preview(characterID)     -> 只读、单角色 LocalObservationPacket
Projector.Deliver(characterID)     -> 校验该角色已有来源后追加缺失观察
Projector.DeliverAll()             -> 全部预检后按角色提交；返回计数，无私密正文
Simulator.SyncCharacterObservations()
                                  -> 同步身份注册与当前世界版本，再分发日志观察
```

桥接方法为显式入口，未自动插入旧 RunDay 或世界启动过程。本次不重启服务，不会令用户已有世界在浏览或加载时自动产生认知文件。2B-4 应先同步再读取 CognitionStore；Preview 只是当前日志投影，不替代已有认知分支校验。

观察增加可选 `speaker` 与 `location` 字段；旧认知文档仍可读取。`public_statement` 在此表示向明确受众表达的陈述，**不表示所有人物都知情，也不保证内容为真**。不自动添加说话人到受众，不生成任何 belief、goal 或 summary 记录。

稳定观察 ID 包含世界、人物、事件和条目序号；SourceID 记录原始日志行的 SHA-256 和条目序号。重放对已存观察逐字段核对，正文、受众、作者元数据或来源改变时拒绝继续，不做静默纠正。

日志按连续版本解析，可从已保存世界快照之后的版本开始；未知受众、重复受众、多受众第一人称观察、重复命令、版本跳跃、重复 JSON 键、不完整行或未知 Occurrence 类型均明确拒绝。缺少日志时返回 MissingJournal，不能从世界状态、旧记忆或作者文本补造观察；若已有投影失去日志来源，则停止。

当前每次分发扫描完整日志，最多 64 MiB；单角色认知仍受 8 MiB 上限约束，超限失败而非截断。游标索引、增量缓存和长期归档不在本步实现。世界/角色调用方必须串行提交与同步；本步没有跨进程日志快照或事务锁。

## 文件与验证

- `internal/characteragent/visibility.go`：局部投影、精确受众、来源核对和幂等投递。
- `internal/characteragent/cognition.go`：可选说话人/地点元数据，以及复用已有目录锁的内部原子追加接口。
- `internal/characteragent/private_files.go`：从迁移文件抽出有界读取、路径检查、摘要与重复键检查，供事件读取和旧迁移复用；不读取迁移内容。
- `internal/sim/character_agents.go`：显式 Simulator 桥接。
- 对应 visibility、Simulator 桥接及原迁移测试覆盖。

以下均通过，使用真实 StateEngine 提交的临时日志和固定数据，无真实模型请求：

1. 五人局部观察、私语精确受众、同房间未被列为受众者不知情。
2. 发言保持原文和说话人，不将可能的谎言改为可信信念。
3. 角色后来移动不丢弃过去合法获知的内容；转述必须有新事件并保留转述者。
4. 预览不写，重复分发不增加文件版本或条目，不读取作者 Reason/Changes/世界状态秘密或旧记忆兜底。
5. 注册世界版本之外的日志尾部不分发；首人称多受众、未知/缺失受众、坏 JSON/重复键/不完整行/版本跳跃拒绝，错误不回显私有 canary。
6. 同版本来源变更或已投影来源消失时拒绝，不覆盖认知。
7. I/O 中断后重试补齐且不重复；任一角色认知损坏时全部角色写入前预检失败。
8. Simulator 桥接不请求模型、不更改世界状态，离场景人物没有收到私语。

命令：`go test ./...`、`go build ./...`、`go vet ./...` 及 `go test -race ./internal/characteragent ./internal/sim ./cmd/world-migrate-memory` 均通过。原有 Windows 符号链接子测试仍因权限跳过。
