# 2A-6：固定五人集成验收

## 实施判断

- 已确认问题：此前注册表、配置接口和操作台分别测试，缺少从真实磁盘世界加载、修改配置、重新加载、生命周期变化到凭据检查的组合验收。
- 优先级：P1 配置与角色注册基础；覆盖 P0 的版本冲突、数据保留与凭据边界。
- 可验证收益：确定五个人物能获得稳定身份，并按三档/人物覆盖解析模型；重载和生命周期同步不改变已保存设置，错误请求不落盘。
- 最小证明：单个端到端配置集成测试，使用临时目录、正式世界实例构造函数、正式 API handler 与两个本机 mock 模型服务。测试不运行模拟，不请求真实模型。

本项只新增 `world_agents_acceptance_test.go` 和验收记录；没有修改生产管线，也没有改动已有用户世界、配置或小说。

## 固定样本

五个角色均位于白室；角色标记仅用于验证默认档位，不是完整人设或死亡游戏规则实现。

| 人物 | 初始默认重要性 | 保存后的模型引用 | 解析来源 |
|---|---|---|---|
| 林砚 | 核心 | a / m1 | 核心档位 |
| 沈雾 | 核心 | a / m1 | 核心档位 |
| 顾衡 | 重要配角 | a / m1 | 人物独立覆盖 |
| 陆离 | 重要配角 | b / m2 | 配角档位 |
| 苏眠 | 背景 | b / m2 | 背景档位 |

`a`、`b` 是两个独立的本机 HTTP mock 服务，`m1`、`m2` 是测试模型名。配角/背景配置额外包含输出预算 1200、上下文预算 6000、并发上限 1，验证整个配置文档在重载后保持一致。

## 通过的验收

1. 将五人人物快照保存至临时 `world_state.json`，使用 `worldServer.newInstance` 实际加载路径自动注册，无需测试直接调用注册函数。
2. 五个人均有稳定 Agent ID 和私有目录，主角、对手、普通参与者及临时人物映射到预期三档。
3. 通过正式配置 API 保存档位及顾衡的模型覆盖；Agent 列表返回预期模型，且 `autonomous_runtime=false`。
4. 重新构造 server/instance 并从磁盘加载，注册表、配置文档、预算及模型解析保持一致。这里是同一测试进程中的对象重建，不是独立进程重启测试。
5. 无效 Provider、注入凭据字段和过期配置版本全部拒绝；保存前后 `agent_runtime.json` 字节相同。
6. 固定快照中将顾衡设为死亡、再恢复活动，分别重建实例。Agent ID 不变，状态在休眠/活动之间改变，人物模型覆盖及全部配置文件保持不变。
7. 给五个人写入不同私有标记文件，验证重载和生命周期同步没有修改或复制它们。这是文件边界验收，不代表认知隔离或请求隔离已经实现。
8. 新建另一个临时世界，使用相同五人人物名，获得不同 World ID/Agent ID；不继承前一世界的配置文档或私有文件。
9. Provider 留空密钥的局部修改保留原密钥及隐藏高级参数；所有经测试辅助函数检查的 API 响应不出现私有标记。
10. 递归检查首个世界的所有文件，没有 Provider 密钥、高级参数私有标记或被拒绝的注入密钥。
11. 自动注册、读取、保存和重载对 mock 模型的请求数为零；显式测试两个服务时各发一次短请求，校验独立地址、认证和模型名，共两次本机请求。

## 结论与边界

**2A 配置与注册阶段全部验收完成。** 现在可以通过操作台管理多个 API 服务，按人物重要性分配模型并持久保存。尚不能把五个人交给独立模型请求运行；当前配置页也明确提示这一点。

本测试没有证明角色思想独立、跨角色知识不泄露、牌局规则正确、模型调用成本受控或小说质量改善。普通私有目录与模型引用并不等于这些能力；后续必须分别验收。

下一项是 **2B-1 CognitionStore**：在每角色目录中定义独立、可审计的观察/信念/目标等认知文档及读写边界。接着才是旧记忆可逆迁移、按受众分发已提交事件、独立请求和多 Provider 调用路由。不能将作者计划或全局事实直接复制给各角色。
