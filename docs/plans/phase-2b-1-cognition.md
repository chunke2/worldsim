# 2B-1：每角色 CognitionStore

## 修改前的四个判断

1. 已确认问题：角色目前只有稳定身份和目录，没有独立、带来源、可审计的认知存储协议；不能将目录独立等同于思考独立。
2. 优先级与层次：P1 角色认知基础；原子写入、版本冲突和损坏保留属于 P0 数据安全。
3. 可验证收益：存储对象只操作一个已注册 Agent；认知只能引用本角色已存观察或更早的认知记录；修订保留旧记录；失败不发布版本。
4. 最小证明：临时五人目录测试身份绑定、来源约束、读写独立、重载、并发 CAS、错误写入、损坏保留。无模型调用、无现有世界操作。

## 决策

- 路径沿用 2A 的 `agents/{稳定哈希 AgentID}/cognition.json`；原计划中的按人物名目录示意以此为准。
- 每个 Store 在构造时绑定注册表中的 WorldID、AgentID、CharacterID，不能接受调用者指定文件路径，也不提供聚合读取接口。
- 未初始化时读出 revision=0 的空文档，不创建文件；首次显式追加才写入。
- 观察与认知分开保存：观察包含接收者、类型、来源标识、事件标识和世界版本；认知包含类型、摘要、置信度、来源 ID、状态和替代关系。
- 只允许追加，记录 ID 在角色文档中唯一。信念修订、目标完成或计划废弃通过新记录 supersedes 旧记录，不覆盖旧文本；当前状态可从未被替代的记录推导。
- 来源可以是本角色观察或更早的认知记录，形成无循环的来源链。观察到一句谎言只证明听见这句话，不证明陈述内容为真。
- 同一原子文件提交观察和认知，避免两个文件写入一半。使用乐观版本检查；读时严格校验身份、结构和来源。损坏文件拒绝读取，不重置或自动覆盖。
- 若观察所属世界版本高于注册表当前世界版本，读取和追加均拒绝，保留原文档供显式分支恢复。世界同步完成后才能写入新观察，避免回档后直接读取未来事件。
- 原始 reasoning、作者规划和提示词不是可接受的记录类型；自由文本仍需由后续调用层选择和验证，类型检查无法证明文本语义安全。

## 当前边界

Store 是受信任的本机运行时组件，不是进程沙箱或用户权限系统。拥有同进程文件权限的代码仍能打开其他文件。认知来源的事件真实性、受众和内容匹配交由 2B-3 投影器验证；Store 本身不能仅凭事件 ID 证明该角色真的看到了事件。角色请求隔离将在 2B-4/2B-6 验收。

回档保护目前依据世界版本数值，无法识别两个分支在相同版本号下的不同事实；尚未实现认知快照恢复或分支 ID。禁止据此宣称已完成认知回滚。后续分发层需验证事件仍属于当前事实分支，显式分支恢复前不应继续运行该角色。

本步不接入现有模拟循环、不迁移旧记忆、不新增前端或 HTTP 读取入口，不改变 API 配置或用户世界。既有记忆不会自动进入新认知。

## 实现与验证

### 文件与接口

- `internal/characteragent/cognition.go`：新增存储、数据类型和校验，无模拟循环接入。
- `internal/characteragent/cognition_test.go`：五人及边界测试，所有数据位于测试临时目录。

```text
NewCognitionStore(worldDir, characterID) -> 已注册的单角色 Store
Store.Owner()                         -> 世界/Agent/人物身份值
Store.Read()                          -> 脱离内部引用的完整历史文档
Store.Append(expectedRevision, observations, records)
                                      -> 原子追加并返回新版本
State.CurrentRecords()                -> 未被替代的记录，包括已完成/废弃状态
```

观察类型：`direct_observation`、`public_statement`、`private_report`、`rumor`、`profile`。前四种必须携带非空事件 ID 和正数世界版本；`profile` 表示受信任的自身设定输入，不能伪装事件收据。Store 不读取世界书来自动生成该资料。

认知类型：信念、假设、目标、恐惧、偏见、承诺、计划、关系判断、近期记忆、长期记忆和摘要。每条记录显式携带 Owner；即使不同角色使用相同本地来源 ID，直接复制另一个角色的记录仍会被拒绝。置信度可选，范围 0–1；状态为 active/resolved/abandoned。

`AddedRevision` 由 Store 赋值，调用者必须传 0。ID 在当前角色整个文档内唯一；重复观察不会覆盖旧观察，投影器将来需处理重放去重。引用必须存在于同一角色，且不晚于该记录；同批认知按提交顺序解析，拒绝循环与前向引用。替代只允许指向同类型且仍为当前状态的旧记录。

存储上限为每文档 8 MiB、单条文本 32768 字节；超限明确拒绝，不静默截断。尚未实现自动归档、压缩或检索，长期运行时需要后续策略。沿用注册表的进程内目录锁，串行化本世界读写与身份同步；不支持多进程同时编辑同一目录。

### 验证结果

以下通过：

- `go test ./internal/characteragent -run Cognition -count=1 -v`：10 项顶层测试及边界子测试。
- `go test ./...`、`go build ./...`、`go vet ./...`。
- `go test -race ./internal/characteragent`：注册、配置与认知存储包的竞态检测通过。
- 五人私有 canary 存取与重载、同名跨世界身份、跨角色记录（相同本地 ID）和外部来源拒绝。
- 只读无副作用、缺失分区诊断、未知人物拒绝、信念修订保留历史、目标完成和本地来源摘要。
- 来源缺失/循环/前向引用、重复 ID、原始 reasoning/草稿/作者规划/世界事实类型、NaN 置信度、未知 JSON 字段及多段 JSON 拒绝。
- 并发同版本仅一个写入成功；临时文件写失败后重试仍从原版本开始；损坏/外来/超限文件均保留。
- 注册表替换拒绝，世界回退后的未来版本记忆拒绝且不删除。

符号链接重定向检查已实现；本机 Windows 没有创建测试符号链接的权限，该子测试明确跳过，不计为已验证通过。其他检查与测试正常运行。本步没有前端改动，不需要重新构建 UI 或重启服务。

2B-2 才处理旧记忆的可逆迁移。未经来源验证的旧文本不能直接当作新的可信观察；必须保留原文件，并为迁移结果标记来源与不确定性。
