# 2B-4：独立 CharacterAgent 请求

## 修改前判断

1. 问题：已有身份、局部观察与认知文件，但没有单角色请求入口或可验证的模型认知更新协议。
2. 优先级：P1 独立请求；P0 防截断落盘、并发重复请求、过期响应和越界来源。
3. 收益：只从自身 CognitionStore 组装一次请求；严格处理模型输出，不让模型写世界事实或修改别人；成功请求收据与认知同文件原子提交。
4. 证明：固定五人私有 canary、捕获 mock 请求、无共享会话、来源与截断错误、重复 turn、写失败/并发/世界变化测试。

## 设计

传输通过无状态 CompletionClient 注入，模型引用与预算由可信调度层传入；2B-5 实现实际多 Provider HTTP 路由。角色上下文只包含自身资料观察、当前认知及来源闭包，不读取全局世界书、其他人的记忆、迁移隔离内容、API 凭据或作者计划。

模型返回明确的 actor/turn 与结构化认知摘要，不接收 reasoning、世界变更或他人 Owner。来源必须在本次展示的上下文内；ID、Owner 和版本由服务器分配。模型能够形成错误信念，但不能凭空引用未收到的信息。

默认预算保守，重要认知及其来源超过预算则拒绝请求，不默默扩大上下文或截断人设。其余观察按近期优先填入。按角色单飞，重复成功 turn 不再调用模型；世界/认知在请求期间变化时拒绝写入，需新回合重试。

后续阶段按用户指令连续推进：2B-5/6 → 2C → 2D；不在小阶段完成后等待确认。所有验证使用 mock/本机固定接口，不实际运行用户世界或消耗真实 API Token。

已实现 `CharacterAgent.Think`、两消息上下文白名单、保守预算、同角色单飞、严格 JSON/类型/来源/身份校验、结构化更新和原子 ThoughtReceipt；无全局世界书或旧迁移归档输入。无新增认知也保存成功收据，重复成功回合不付费重试；写失败可能已产生外部调用成本，明确报错，不能保证网络 exactly-once。

4 项 CharacterAgent 顶层测试覆盖固定五人独立调用、幂等回合、截断/原始 reasoning/未知字段/错误人物回合/越界来源拒绝、预算拒绝、并发单飞、过期响应和写失败重试。全量 Go 测试/build/vet 与相关包 race 检测通过。语义上的幻觉或恶意 prompt injection 不能仅由类型校验彻底解决，世界事实仍需后续确定性裁决。
