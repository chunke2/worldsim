# 2A-3：人物 Agent 自动注册

状态：已实现并通过测试；角色自主决策属于 2B/2C。

## 本项解决的问题

世界实体尚未拥有稳定 Agent 身份，人物新增、死亡和离场不能驱动 Agent 生命周期。本项属于 2A 配置与注册基础：让一个世界中的五个人物对应五个持久逻辑 Agent，而不是五个共享上下文的提示词角色。

最小证明是固定五人样本：注册产生五个不同身份；重启、重复同步和角色恢复不重新分配身份；死亡及离场不删除记忆；模型调用次数为零。

## 文件与职责

- `internal/characteragent/registry.go`：注册、状态投影、持久化和纯读取。
- `internal/engine/state_engine.go`：增加加锁的深拷贝 Snapshot，防止派生消费者修改真实世界。
- `internal/sim/character_agents.go`：将提交后的世界快照传入注册表。
- `internal/sim/narrative.go`：模拟前后同步，失败轮次也尝试同步已经提交的变化。
- `internal/sim/simulator.go`：新人物提交后同步。
- `internal/sim/snapshot.go`：明确回档后重新投影 Agent 活跃状态。
- `main.go`：在加载、初始化和手动提案提交后接入注册。

## 数据结构

```text
worlds/{world}/
  agent_registry.json       # 世界 ID、注册版本、所观察世界 revision、人物映射
  agents/{agent_id}/        # 独立分区，后续接入角色认知；当前只创建目录
```

世界 ID 在首次注册时随机分配并持久化。Agent ID 从世界 ID 与实体 ID 的组合计算 SHA-256，文件路径使用哈希，不使用人物名，因此中文和路径字符不会直接变成目录路径。

注册表只保存身份、重要性、活跃/休眠状态、休眠原因和首次注册 revision，不复制人物私密记忆或 API Key。

默认档位只在首次注册时推断；后续同步保留保存的设置。主角、对手和核心感情角色为 core，普通和重要配角为 supporting，龙套为 background。

## 一致性与失败恢复

- 同一世界内的多个注册器共享进程内锁，避免并发重复注册和 `.tmp` 写冲突。
- 创建分区成功后才原子发布注册表；中断最多留下空分区，可以重试。
- 相同世界快照不会重写注册表或提高注册版本。
- 损坏的注册表、空实体 ID 会报错，不静默覆盖或猜测角色。
- 世界提交和注册表属于两个不同事务。世界事实已提交但注册表同步失败时，返回明确错误，下一次同步重建派生状态，不撤销已提交事实。
- 普通同步拒绝比注册表更旧的世界快照。明确回档走 `ReconcileAfterRewind`，允许状态回退并保留身份。
- Agent 注册表不随世界快照整体覆盖；未来分支中的人物在旧世界中标记为不存在而休眠，其原 ID 与目录保留。

## 当前限制

现有引擎使用实体映射键（当前通常为人物姓名）作为实体 ID。本项保证相同实体键在重启、休眠和恢复时稳定；人物改名必须在后续显式迁移时保留映射，不能直接删除旧键再创建新键。

跨进程同时写同一世界不在本阶段支持范围内。角色分区当前只是分区目录；独立认知、计划、记忆迁移及模型调用将在 2B 实现。本项不宣称人物已经拥有完整自主决策循环。

注册表的回档同步只处理身份与活跃状态，不等于私有认知和小说作品已实现完整分支回滚。
