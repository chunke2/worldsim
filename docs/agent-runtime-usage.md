# 独立人物运行时：测试指南

此文对应 phase 2A–2D。旧世界默认仍是兼容模式，重新启动新版服务不会自动运行世界或消耗模型 Token。本轮没有操作你的实际世界、API 配置或旧章节。

## 1. 使用新版程序

前端嵌在 Go 二进制中，旧服务不会热更新。使用重新构建的程序并保留原数据目录参数。仓库源码可这样构建：

```powershell
Set-Location D:\dev\WorldSim
go build -o .\bin\worldsim-agent-runtime.exe .
```

启动时传入原有数据根目录（包含 `api.json`、`worlds` 的那个目录），不要把 `worlds` 本身当作根目录。停止旧服务后才启动新版；勿为测试新功能重置旧世界。

## 2. 配置人物与模型

1. 在“操作台 → API 服务 / 角色 Agent 设置”读取配置。
2. 保存你的 Provider、地址、密钥、模型名。可有多个 Provider，也可五人使用同一模型服务。
3. 三档：核心、重要配角、背景；每档选择 Provider、模型、输出预算、上下文预算；单个人可覆盖模型。
4. 把运行方式改为“独立角色运行”并保存。保存和刷新均不发模型请求。

五个人代表五个有自己上下文、记忆和决策收据的逻辑 Agent；不等于五种模型或五个常驻进程。自由模式最多两个人物请求并发；还会受档位和服务限额限制。牌局每次只轮到一人。

下方兼容管线的 off/mock 不能冒充真实角色模型，显式选择 off/mock 后独立模式会拒绝发请求。小说写手使用已保存的写作 API 与 NovelConfig 长文覆盖项，不跟随人物三档模型自动切换。

## 3. 五人死亡牌局

先用新世界或明确的版本副本准备：五名人物均 `alive=true`、`status=active`、在同一个有效房间，有稳定 `world_level.protagonist` 和 `narrative_pov`。人物自己的资料放在各自实体资料中；整体世界书不会直接灌给每个人。

尚未启动独立场景时，点击“初始化五人死亡牌局（零模型请求）”。已初始化的场景不能被按钮覆盖。规则摘要：

- 每人一条生命；J/Q/K 普通牌与万能 A。
- 轮到自己且无待质疑牌：选择自己手中1–3张盖牌，声明当前桌面牌型，可以说谎。
- 下一人选择 accept / challenge，可附带自己的话语。
- 质疑时程序公开翻牌：说谎者扣命，没说谎则质疑者扣命；0命出局。
- 连续三次接受触发公开的生命代价；剩唯一活人结束。

这是固定的简化智斗规则，不是所有骗子酒馆规则或额外特权系统。手牌只发给本人；其他人不能从世界全景获得手牌。

前端初始化默认使用新的服务器随机种子；种子仅在权威状态中保存，不交给人物。测试接口可显式提供固定 seed，以重现相同发牌和裁决。

点击单次推进或启动循环才调用角色模型。后台循环在终局、三轮无有效变化或模型失败时停止。失败后先看审计，手动重试；成功完成的同回合人物请求可复用。

## 4. 观察与调整

人物设置页的“独立角色运行观察”显示回合、行动者、裁决、每人观察和思考数、请求 Token、最近剧情推进来源。

- “私人认知”：作者显式检查该人的目标/信念/记忆与来源，不是原始推理链。
- “调用审计”：接口收到了什么状态、模型路由和用量；received 不代表认知成功落盘。
- 等待、观察和纯对话不自动算有效剧情变化。三轮停滞后，可填写有来源的环境提示或资源条件；作者理由不会给角色看。
- 资源代价目前操作人物的 `money` 余额；不足扣至0。环境条件不会替角色决定如何回应。

Token 数不是金额；未返回用量的失败调用可能仍收费。系统不自动反复调用模型来“修好”失败结果。

## 5. 写小说

独立模式不再等待旧的“三段落/张力/伏笔回收”阈值。固定 POV 观察到至少两次已裁决有效变化后，可显式生成。

每章默认一次正文请求 + 一次 fast 档语义审查；分章和读取列表零模型调用。写手仅拿到对应 POV 与章节时间内的事实包、规则及前章读者摘要。截断、缺摘要、来源/视角/连续性/揭示审查失败均不会发布，已有章节保持不变。

现有兼容模式作品不能自动混入新来源模式；需要新作品分支。固定 POV 如果已死，不会为了写完整结局而自动获得死后的信息。多 POV 的正式章节编排属于下一阶段。

## 验证证据

- 固定五人 mock 独立选择到唯一幸存者，事件重放等于最终状态。
- 跨角色、作者秘密、未来揭示的 canary 不进入对应角色或较早章请求。
- 世界 API 与浏览器使用 mock 验证，未消耗真实模型 Token。
- 全量 Go 测试/build/vet、核心 race 与前端生产构建通过。

这些验证证明请求边界和规则行为；真实模型的智斗水平、文笔、悬念与人物弧光仍需你用小样本评审。
